# v1.7.0

## Overview

We are pleased to announce **API Test Commons v1.7.0**, a feature enhancement and stabilization release focused on dynamic ID-schema handling, OTP/SMTP listener reliability, report and masking improvements, and infrastructure cleanup within the MOSIP Functional Test Framework.

This release introduces a major rework of dynamic identity request generation to support all ID-schema field types, including array-based handle fields, along with support for the AddIdentity v2 endpoint. It also introduces an opt-in full-schema identity template builder, a self-healing SMTP OTP WebSocket listener, always-on masking of large binary payloads in reports, eSignet signup file-upload support, and removal of the standalone authentication-demo-service module.

Version 1.7.0 builds upon v1.6.0 and continues to strengthen test automation reliability, dynamic schema support, reporting diagnostics, and deployment robustness across MOSIP module test suites.

### Key Changes & Required Module-Level Updates

#### 1. Helm Report Volume Configuration Updated

The default storage class for apitestrig report volumes has been changed from nfs-client to nfs-csi.

The static PersistentVolume template has also been removed in favor of dynamic provisioning.

**Action required:** If your cluster does not have an nfs-csi storage class, explicitly configure:

apitestrig.volumes.reports.storageClass

***

#### 2. New Kernel.properties Configuration Keys

The following configuration properties have been added:

* smtpURL
* audit\_db\_schema
* pms\_default\_schema

smtpURL is optional. If it is not configured, the SMTP host is derived from keycloak-external-url.

**Action required:** Add these properties if your module maintains its own overriding copy of Kernel.properties.

***

#### 3. eSignet Data Share Policy Scaffolding Removed

The eSignet Data Share Policy helper functionality introduced under MOSIP-44709 has been removed because it was not used by any active test flow.

This includes related:

* Database schema wiring
* Keyword handlers
* Helper methods

**Action required:** Ensure that module test code does not depend on the removed Data Share Policy helpers in BaseTestCase or DBManager.

***

#### 4. TestCaseDTO Schema-Aware Fields

TestCaseDTO now includes two optional fields:

* requiredSchemaFields
* requiredHandleFields

These fields allow test cases to participate in schema/handle-aware skip logic.

**Action required:** No action is required for existing test cases unless a module wants to make use of the new schema-aware skip functionality.

***

#### 5. New Schema-Based Identity Template Builder

A new SchemaBasedIdentityTemplateBuilder has been introduced to generate identity templates using all fields available in the live IdSchema.

The builder is **opt-in** and is not enabled by default.

Existing required-field identity generation through modifySchemaGenerateHbs remains unchanged.

**Action required:** No changes are required for existing modules unless they want to use the new full-schema identity template generation capability.

***

#### 6. PDF Library Updated

The PDF processing implementation has been migrated from **iText** to **Apache PDFBox 3.0.3**.

The apitest-commons dependency on iText has been removed, and PDF handling has been updated to use PDFBox APIs.

**Action required:**\
If your module test code directly uses iText classes or depends on the iText libraries transitively through apitest-commons, update the module code/dependencies accordingly. No action is required for modules that do not directly use iText APIs.
