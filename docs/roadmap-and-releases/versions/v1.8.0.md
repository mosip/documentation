# v1.8.0

**Release Number:** v1.7.0

**Release Date:&#x20;**<mark style="color:red;">**Coming Soon!**</mark>

## **Overview**

We’re excited to announce the release of **eSignet v1.7.0**, a feature-rich upgrade over v1.6.1 that introduces major advancements in security, enhanced user interaction flexibility, and improved deployment efficiency. This release includes full support for the **FAPI 2.0 Security Profile** (link to feature page), implemented through multiple industry-standard RFCs, and brings dynamic, schema-driven UI enhancements for both Sign-Up and KBI authentication—while ensuring complete backward compatibility with existing authentication flows.

## **Major Highlights**

### **New Features**

#### **Support for FAPI 2.0 Security Profile**

eSignet now implements key RFCs required for FAPI 2.0 compliance, strengthening security and interoperability:

* **Pushed Authorization Request (PAR)(Link to the Feature page in eSignet authentication)** – _RFC 9126_\
  A new PAR endpoint is introduced to support secure, tamper-resistant authorization requests.
* **Demonstration of Proof of Possession (DPoP)(Link to the Feature page in eSignet authentication)** – _RFC 9449_\
  Adds cryptographic proof-of-possession for access tokens, preventing token replay attacks.
* **Authorization Server Issuer Identification (Link to the Feature page in eSignet authentication)** – _RFC 9207_\
  Enhances security by enabling the ‘Authorization Server’ to uniquely identify itself during authorization flows; includes updates to .well-known/oauth-authorization-server configuration.

**FAPI 2.0 support is now fully enabled in eSignet.**\
However, enforcement of the FAPI 2.0 security profile is **client-configurable**. Each client can choose whether or not to enable FAPI 2.0 for their integrations.\
If a client does **not** enforce the FAPI 2.0 profile, their authentication flows will continue to work **seamlessly without any change**.

### **Enhancements**

#### **Dynamic Schema-Driven Sign-Up UI(Link to the Feature page in eSignet Signup Features)**

The Sign-Up experience has been improved with the UI that can now be generated dynamically based on a backend-driven UI schema.\
This leverages a JSON form-builder library for improved flexibility and faster configuration changes.

#### **Dynamic Schema-Driven KBI Authentication UI(Link to the Feature page in eSignet Signup Features)**

The KBI authentication UI is now also fully dynamic and powered by the same schema-based JSON form builder, enhancing consistency and maintainability.

#### **Improved Deployment Scripts(Link to the Feature page in eSignet Signup Features)**

Deployment scripts for the eSignet service have been refined to simplify setup, reduce configuration overhead, and ensure smoother deployments across environments.

The properties listed below are newly added to the eSignet default configuration. For a comprehensive view of all configuration properties in eSignet, please [refer here](https://github.com/mosip/esignet/blob/master/esignet-service/src/main/resources/application-default.properties).
